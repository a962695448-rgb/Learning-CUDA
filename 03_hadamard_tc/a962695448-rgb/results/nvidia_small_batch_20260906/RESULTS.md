## 正确性与范围

实际完成 M={1,17,64}、N={64,256}、FP16/BF16、scale={1,1/sqrt(N)}，24 个配置，每配置7个确定输入。三轮均全部通过：168 个不同输入、共504次输入验证执行。每个32/64/128/256版本的 transform 全元素位一致、fused 与分步 packed/scales 位一致、独立 CPU FP32 INT4 除法/RNE/打包全行一致。各轮 Dao 最大绝对误差与抽样行 FP64 稠密参考误差均为0。

这不是重新运行原1876 CLI或1800 Dao矩阵；未测的120个holdout配置与本轮未测N16/N128不能计为通过。性能只测transform，量化只作正确性检查。

## 性能与负例

每轮5组，64个互异输出的私有CUDA Graph、每组20次replay；25次API预热及5次Graph预热。三个独立进程重排配置及方法顺序，所有线程与Dao使用同一输入；保留3600个原始组样本（两口径×24配置×5方法×5组×3轮）。事件原始区间以ms保存，同时提供每调用ms/us；Graph为捕获GPU工作加均摊replay开销，不能称孤立kernel延迟。

## 失败保留与复算

首次调度器的run1成功后，紧接着的run2在Torch导入前被utilization门禁拦住，预检记录20%，正确性与计时条目均为0；该失败日志/JSON和suite退出1原样保留。后续确认前一进程退出且GPU空闲，只新增调度层最多60秒、连续两次0%的等待，用完全相同冻结worker续跑run2/run3。主统计明确使用以下三份成功报告，不覆盖失败文件：

```bash
python raw/analyze_runs.py --phase screen --protocol raw/protocol.json --output recomputed   raw/runs/screen/run1.json raw/runs/screen_resume/run2.json raw/runs/screen_resume/run3.json
python verify_archive.py
```

本地复算结果为VERIFIED、192条逐配置/线程/口径比较，两个CSV与服务器生成版本字节一致。`raw/derived/screen/selection.json` 的候选列表为空；按照首次GPU运行前冻结的协议，不执行120项holdout。调度失败与不采用候选是不同原因，均保留证据。

`raw/`为37个严格白名单文本文件：36个传输清单对象及清单本身，全部保持服务器原字节，无脱敏改写。`archive_manifest.json`核验公共档案中的每个其他文件；`.gitattributes`避免Git自动换行改变原始哈希。没有公开凭据、私有访问地址或二进制。GPU前后快照包含原448MiB驻留context，身份无法在容器完全对应，不能声称独占GPU；结束时GPU为0%。
