# 普通调用的模块、输出缓冲和顺序诊断

本轮为诊断，**没有采用新的计算内核，也没有改写两次历史 REJECT**。受测生产计算对应 b49fff4，候选为已归档的第二版；控制A/B从同一源码路径、同一编译参数、等长不同模块名构建。

## 先前慢例的具体问题

旧版报告中最严重的 FP16 fused / rows16387 / N2 allocating，独立中位数比为0.809675；9组成对记录中5组候选更快，配对比值中位数为1.007713。前6组两侧均有大幅起伏，最后3组接近8微秒。这不构成稳定慢23%的证据，也不构成改写旧判定的依据。原始数据和原有采纳规则不变。

## 本轮固定设计

3个独立进程循环交换模块加载顺序；4种有依据的配置×5种调用/输出条件×18组×3个模块，共3240个计时块，每块5000次。18组完整覆盖六种模块测量顺序与三种独立输出池轮换；共享池条件下三个模块使用相同输出张量。记录原始时间线、进程/线程CPU时间、调度/缺页/GC计数和可读CPU频率。

所有模块/缓冲区组合均先核对独立CPU数值参考，案例结束再核对输出和输入不可变性。单机RTX4090；重启后显示PCI地址由此前的37变为9D，记录中不直接用两个会话的绝对时间相除。

## 结果

20种条件均满足预设的同源A/A 5%范围，IQR/中位数没有超过10%的宽波动标记。没有任何条件在全部三个进程中，同时满足两种统计口径的稳定超过5%候选退化或加速标准。

| 配置 | 共用/轮换输出池：配对比值范围 | 分配式调用：配对比值范围 |
|---|---:|---:|
| FP16 fused 65536×8 | 0.981935–1.012747 | 0.965565–0.991594 |
| FP16 fused 16387×2 | 0.993795–1.018862 | 0.974117–0.984733 |
| BF16 Hadamard 257×16 | 0.995619–1.034012 | 0.973508–0.990091 |
| FP16 original fused 65536×8 | 0.999892–1.000355 | 0.999834–1.000211 |

比值定义为控制A耗时/另一模块耗时，接近1表示接近持平。全部候选比值：独立中位数0.963083–1.036172，配对比值中位数0.965565–1.034012。同源码双模块A/A的相应范围为0.975662–1.032983和0.973501–1.040054。因此，几个百分点的差异并不能直接归于设备内核改动。

每个进程只有一个计时块记录了GC回收，所有块均有进程级调度计数变化。这些计数用于排查关联，不能直接证明旧慢例由GC、调度、缓冲地址或模块布局导致。

静态汇编显示两版 quantized<true>/quantized_out<true> 的记录指令数分别同为380/396，opcode与直接调用名称序列相同；dispatch<true,true> 则从97变为277。计数包含冷/错误分支，且callee、操作数和重定位不同，不能当作动态成本。

## 限制和下一步

这是四种配置的归因诊断，不能代替原完整588设备+588主机矩阵的采纳验证。先前两版仍为REJECT，生产内核不变。下一项实现实验可保持现有kernel入口和host派发结构，在设备实现内整合成对蝶形，并同步检查CLI网格；之后仍需完整正确性与冻结的性能范围，而不是仅复测这四个案例。
