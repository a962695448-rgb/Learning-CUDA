# NVIDIA contiguous256 寄存器布局实验

这是独立假设，未修改生产源码，也不扩展上一轮 small_batch 的搜索或采用其失败候选。固定 N256、128 线程，比较同一个扩展内的 `layout="original"` 与 `layout="contiguous256"`。源码及协议冻结后才允许构建与实机检查。

原布局 `index=lane+32*k` 改为 `index=8*lane+k`。先在寄存器执行全局索引 bit0/1/2 的三个蝶形阶段，再用 warp shuffle 执行 bit3..7；阶段顺序、低位 `a+b` 和高位 `a-b` 都保留。scale 后先 RNE 到原 FP16/BF16 storage，再转 FP32 做 maxabs/7、精确除法与 INT4 RNE。相邻两个量化值在同一 lane 寄存器内打包。

实际输入地址16B对齐时采用uint4加载，按16-bit原始位模式解释；合法2B偏移的contiguous输入走标量路径，不添加输入对齐限制。transform输出独立检查16B对齐；packed输出独立检查4B对齐。向量解包没有把低对齐的局部T数组强转uint4。输出均由原PyTorch适配器分配，因此只把输入错位作为接口实测范围，不声称已有用户传入输出缓冲区的API。

只读符号审查已核对256个逻辑元素的8个阶段，表达式及操作数顺序与原实现相同；源码静态复核未发现阻塞问题。这些检查不是GPU正确性或性能通过。

`protocol.json` 固定24配置：M={1,17,64,257,4096,16384}、N256、FP16/BF16、scale=1或1/16。全部检查包括原/新位一致、融合/分步一致、CPU全元素量化、FP64抽样、输入guard不变、非默认stream以及2B偏移输入。独立量化tie检查覆盖负数、正数、零和半整数。计时分别为 transform原/新/Dao 与 fused原/新，每方法64个独立输出Graph、三进程、五组重排。原始事件以ms保存，按实际调用数折算；不把Graph时间说成纯kernel，不把不同实验/硬件作为分母。

固定Dao源的 `csrc/fast_hadamard_transform_common.h:135` 使用未检查偏移的16B向量加载。因此只在2B偏移正确性检查中，Dao接收位完全相同的对齐副本，且比较副本与输入的全部字节；原/新实验路径始终接收真正错位输入。性能输入本来就对齐，所有方法共用同一输入，不计时复制。这样保留参考数学及错位输入检查，同时不向参考实现传入不满足其向量加载要求的地址。

尚未运行GPU。完整的源/执行文件清单将在计时前冻结，任何失败都保留；不会更改原参考期望或降低精度要求。
